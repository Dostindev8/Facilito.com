# ADR-001: PostgreSQL RLS as tenant boundary

## Context
Facilito is multi-tenant. Isolation must hold even if application code forgets a WHERE clause.

## Decision
Use PostgreSQL Row-Level Security with `ENABLE` + `FORCE ROW LEVEL SECURITY` on every business table. Application role `facilito_app` has `NOBYPASSRLS`. Each transaction sets `app.tenant_id` via `set_config(..., true)`. Missing tenant context yields zero rows.

## Alternatives
- App-layer filtering only: rejected (single bug leaks tenants).
- Schema-per-tenant: rejected for MVP cost and migration complexity.

## Consequences
Repositories must open a transaction and set tenant context. Isolation suite in CI is mandatory. Superuser never used by the API process.

## Cost
Negligible infra cost; engineering cost in transaction discipline.
